# 教学设计与课程脚本说明

## 1. 学习者画像

- 高校计算机相关专业低年级学生。
- 用过 GitHub 下载代码，但只会在网页上点“Download ZIP”。
- 听说过分支和冲突，遇到冲突时倾向于删除仓库重来。
- 能在浏览器中完成拖拽、点击和简单命令行操作。

## 2. 学习目标

完成三个实验后，学习者能够：

1. 解释分支与提交的关系，并独立创建、切换功能分支。
2. 区分快进合并与非快进合并，说出 merge commit 的两个父提交分别来自哪里。
3. 读懂 `<<<<<<<`、`=======`、`>>>>>>>` 冲突标记，比较两版内容并做出有理由的合并决策。
4. 完成一次冲突后的 `git add` 与 `git commit`。

## 3. 三个实验的认知阶梯

| 阶段 | 实验 | 新概念 | 认知负荷控制 |
| --- | --- | --- | --- |
| 建立直觉 | 01 分支与快进合并 | 分支指针、HEAD、Fast-forward | 只有一条功能分支，不出现分叉 |
| 增加并行 | 02 并行开发与合并提交 | 分叉、两个父提交、merge commit | 两条分支，命令重复出现，降低记忆负担 |
| 面对真实问题 | 03 冲突解决 | 冲突标记、三方合并、解决决策 | 只冲突一个文件的一行，提供并排对照 |

每个实验只引入一个新维度：先有分支，再有并行，最后才有冲突。这样学习者的工作记忆不会被“分支 + 冲突 + 合并”同时占满。

## 4. 反馈设计

### 正确命令

执行后立即发生三件事：

1. 终端输出真实风格的命令结果。
2. 提交图节点、分支标签或 HEAD 移动。
3. 步骤卡推进到下一步，进度条增长。

视觉、文本和状态三个通道同时确认，强化因果关系。

### 错误命令

不扣分、不锁定，只给一条针对当前目标的提示。例如在“创建并切换分支”步骤选择 `git branch feature/readme`，提示会指出它只创建不切换，并给出 `git switch -c`。

错误提示避免三种写法：

- “命令错误，请重试”（没有信息）。
- “正确答案是 …”（鼓励试错而非理解）。
- 长篇 Git 手册摘录（超出当前工作记忆）。

### 冲突解决

冲突面板并排展示 `HEAD` 与 `feature/header` 两版内容，提供三个选项：

- 保留双方，合并成一句（正确）。
- 只保留 HEAD（错误，丢失队友改动）。
- 只保留对方（错误，丢失主线改动）。

错误选项会解释“丢失了什么”，把决策从“猜哪个按钮能过关”转向“这次合并要保留哪些信息”。

## 5. 课堂使用建议

### 45 分钟课堂

| 时间 | 环节 |
| --- | --- |
| 5 min | 用一张图解释 commit / branch / HEAD |
| 10 min | 学生独立完成实验 01 |
| 10 min | 教师演示实验 02 的分叉与合并提交 |
| 12 min | 学生完成实验 03，两人一组比较解决策略 |
| 8 min | 回到真实仓库：创建分支、提交、发 PR |

### 课后作业

- 在自己的 GitHub 仓库创建一个 `feature/` 分支，提交一次文档修改并合并。
- 在课程仓库的 Issue 中贴出 `git log --graph --oneline --all` 的输出，解释其中一个 merge commit 的两个父提交。

## 6. 评估方式

| 维度 | 证据 |
| --- | --- |
| 概念理解 | 能用自己的话解释“分支只是指针” |
| 操作能力 | 独立完成三个实验，不依赖提示 |
| 冲突决策 | 能说明为什么保留双方，而不是二选一 |
| 迁移能力 | 在真实仓库完成一次分支合并 |

## 7. 已知限制

- 沙盒不执行真实文件操作，学习者仍需在真实仓库练习。
- 只覆盖内容冲突，不覆盖删除/重命名冲突。
- 没有账号系统，教师无法直接查看学生进度。
- 课程脚本目前写死在 `assets/js/lessons.js`，教师改课需要改代码。

这些限制已列入 [roadmap.md](roadmap.md)。
